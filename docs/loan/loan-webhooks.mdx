# Webhooks de Empréstimo

Os webhooks de empréstimo avisam quando um pagamento foi recebido e quando o
empréstimo foi quitado, sem precisar consultar
[`GET /api/v1/loan/operation/{id}`](./how-to-track-a-loan-using-api) de tempos
em tempos.

## Eventos

| Evento | Quando dispara | `operation.status` |
| --- | --- | --- |
| `LOAN_PAYMENT_RECEIVED` | Um pagamento foi recebido e abatido do saldo devedor: uma parcela, a quitação ou um pagamento de recuperação | `ACTIVE`, `SETTLED` ou `WRITTEN_OFF` |
| `LOAN_SETTLED` | O pagamento zerou o saldo devedor e o empréstimo foi quitado. Chega logo depois do `LOAN_PAYMENT_RECEIVED` desse mesmo pagamento | `SETTLED` |

Cada pagamento gera **um** `LOAN_PAYMENT_RECEIVED`. O pagamento que quita o
empréstimo gera também um `LOAN_SETTLED`, com o mesmo payload.

## Quem recebe

Os eventos só existem para empréstimos originados pela
[API](./how-to-originate-a-loan-using-api), e vão para:

- a empresa que originou o empréstimo (a dona do `APP_ID` usado em
  `POST /api/v1/loan/operation`);
- a empresa parceira dona do fundo que emprestou, quando o empréstimo foi
  originado por uma empresa afiliada a ela.

Quando o parceiro origina pelo próprio fundo, recebe o evento uma vez só. Cada
empresa recebe apenas pelos webhooks que ela mesma cadastrou para o evento.

## Como cadastrar o webhook

Cada webhook se inscreve em **um** evento. Para acompanhar pagamentos e
quitação, cadastre um webhook para `LOAN_PAYMENT_RECEIVED` e outro para
`LOAN_SETTLED`.

### Pelo aplicativo

1. Acesse a lista de **[API/Plugins → Webhooks](https://app.woovi.com/home/api/list)**.
2. Clique em **[Adicionar webhook](https://app.woovi.com/home/openpix/webhook-create)**.
3. Informe a **URL** do seu endpoint.
4. Selecione o evento de empréstimo.
5. Salve e mantenha o webhook **ativo**.

### Pela API

```bash
curl --request POST \
  --url https://api.woovi.com/api/v1/webhook \
  --header 'Authorization: {APP_ID}' \
  --header 'Content-Type: application/json' \
  --data '{
    "webhook": {
      "name": "Empréstimo - pagamento recebido",
      "event": "LOAN_PAYMENT_RECEIVED",
      "url": "https://seu-dominio.com/webhooks/woovi",
      "authorization": "opcional-token-que-voce-recebe-de-volta",
      "isActive": true
    }
  }'
```

Repita com `"event": "LOAN_SETTLED"`. Veja [Webhook API](../webhook/webhook-api.mdx)
para o restante da API de webhooks.

## Payload

[`GET /api/v1/loan/operation/{id}`](./how-to-track-a-loan-using-api#exemplo-de-resposta)
e já com o pagamento abatido, e o objeto `payment` com o pagamento que gerou o
evento:

| Campo de `payment` | Significado |
| --- | --- |
| `id` | Identificador do pagamento; é o mesmo `id` em `operation.repayments[]`. |
| `amount` | Valor abatido da dívida, em centavos. |
| `lateFee` | Multa e juros de atraso cobrados junto, em centavos. |
| `channel` | `PIX_MANUAL` (cobrança Pix), `PIX_AUTOMATICO` (Pix Automático) ou `RECOVERY` (recuperação de empréstimo baixado). |
| `endToEndId` | Identificador do Pix recebido. |
| `txid` | `txid` da cobrança paga, o mesmo devolvido em [Pagar empréstimo](./how-to-pay-a-loan-using-api). Use para dar baixa no seu sistema. `null` quando o pagamento não veio de uma cobrança. |
| `paidAt` | Quando o pagamento foi recebido. |

## Validando e respondendo

- **Assinatura**: valide o header `x-webhook-signature` (RSA-SHA256) com a chave
  pública da Woovi. Veja [Validação de assinatura](../webhook/seguranca/webhook-signature-validation.mdx).
  Se o webhook tiver uma HMAC secret key, o header `x-openpix-signature` também
  é enviado, por compatibilidade ([HMAC](../webhook/seguranca/webhook-hmac.mdx)).
- **Resposta**: qualquer `2xx` confirma o recebimento. Qualquer outra resposta,
  ou um _timeout_, gera nova tentativa. Veja
  [Retentativas](../webhook/webhook-retry.md) e [Timeout](../webhook/webhook-timeout.md).
- **Duplicidade**: a entrega é _at least once_, então o mesmo evento pode chegar
  mais de uma vez. Deduplique pelo par `event` + `payment.id`.

:::tip Não perdeu nada?
Se o seu endpoint ficou fora do ar, consulte o empréstimo com
[`GET /api/v1/loan/operation/{id}`](./how-to-track-a-loan-using-api): o
`status`, o `outstanding` e os `repayments[]` dele são sempre o estado atual.
:::
