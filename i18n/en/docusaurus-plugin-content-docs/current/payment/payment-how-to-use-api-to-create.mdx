## Creating Payments with the API

We provide the _endpoint_ `/api/v1/payment` so you can create
a new _payment_ for the respective affiliated company.

You can find the documentation for this _endpoint_
[here](</api#tag/payment-request-access/POST/api/v1/payment>).

As part of the request `body`, there are two payment modes: by Pix key and by QR Code:

1. By Pix key, the fields `value`, `destinationAlias`, `destinationAliasType` and `correlationID` are required.
2. By QR Code, the fields `qrCode` and `correlationID` are required.

Below is the description of each field, including the optional ones:

- **`value`**: The amount in cents of the payment to be created.
- **`destinationAlias`**: The destination Pix key of the created payment, in the format of its type. Phone numbers must always be in international format, with `+55` and the area code (`+5511912345684`). See [Pix key format](./pix-key-format.md).
- **`destinationAliasType`**: The type of the destination Pix key of the created payment. Must be one of the following values: CPF, CNPJ, EMAIL, PHONE, RANDOM. Always send the type: a key that is both a CPF and a mobile number (ambiguous key) sent without it is rejected with `400`. See [Ambiguous key: CPF or phone](./pix-key-format.md#chave-ambígua-cpf-ou-telefone).
- **`qrCode`**: The QR Code to be paid
- **`correlationID`**: A unique identifier for the payment.
- **`comment`**: Comment attached to your payment when the transfer is made.
- **`sourceAccountId`**: The source account ID. If not provided, the default account is used.

After making the request, if everything went well, the request _status code_ will be `2xx` and the response `body`
will contain the information about the newly created `payment`.
